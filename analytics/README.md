# Zepto Analytics Pipeline

This module implements the Zepto capstone analytics workflow from profiling and cleaning through classification, imbalance handling, hyperparameter tuning, and a regression side-task.

## Files

- `01_eda.py` — the **only** script that calls `sns.load_dataset("titanic")`. It profiles the raw dataset, immediately creates the offline CSV fallback, cleans it once, creates the EDA charts, computes required statistics, and writes results.
- `02_modeling.py` — reads the same `titanic.csv`; it does not call `sns.load_dataset`. It performs the stratified split, train-only preprocessing, three classifiers, evaluation, imbalance comparison, Random Forest tuning, regression, and model saving.
- `titanic.csv` — generated by `01_eda.py` and then overwritten with the cleaned DataFrame. This is the single offline fallback used by modeling.
- `plots/` — generated charts.
- `outputs/` — generated text/CSV/Markdown results.
- `models/best_model_pipeline.joblib` — generated complete fitted preprocessing + classifier pipeline.

## Setup

From the repository root:

```cmd
pip install -r analytics\requirements.txt
```

The existing repository-level `.venv` can be used; a separate virtual environment is not required.

## Run end to end

Run these commands in order:

```cmd
python analytics\01_eda.py
python analytics\02_modeling.py
```

The first run of `01_eda.py` needs internet access because Seaborn's Titanic loader downloads/caches the dataset. After that, the committed `analytics/titanic.csv` is the offline fallback.

Do not run `sns.load_dataset("titanic")` in `02_modeling.py`. It intentionally reads the CSV so the module has one dataset-loading point.

## Data-loading and cleaning decisions

The raw dataset is loaded exactly once:

```python
df = sns.load_dataset("titanic")
```

It is immediately written using:

```python
df.to_csv("titanic.csv", index=False)
```

The cleaned DataFrame is then written back to the same `titanic.csv`, so the modeling stage consumes the same cleaned dataset.

For the standard Seaborn Titanic data, the affected columns are approximately:

| Column | Missing percentage | Strategy |
|---|---:|---|
| `age` | 19.87% | Median imputation |
| `embarked` | 0.22% | Drop affected rows |
| `deck` | 77.22% | Drop column |
| `embark_town` | 0.22% | Drop affected rows; redundant with `embarked` |

The exact percentages are calculated and printed by `01_eda.py`, so the submitted output records the measured values from the actual run.

The threshold rule is:
- below 5%: drop affected rows;
- 5%–30%: impute;
- above 30%: drop the column or explicitly encode missingness. Here `deck` is dropped because more than three quarters of its values are missing and reliable imputation would be difficult.

`age` uses its median. `embarked` and `embark_town` have only a tiny number of missing rows, so those rows are removed. `embark_town` is also redundant with `embarked`.

## EDA requirements covered

`01_eda.py` produces:
- `df.info()`, `df.describe()`, and `df.shape`;
- missing-value percentages;
- age and fare histograms and box plots;
- IQR outlier counts;
- fare mean, median, and mode plus a skewness conclusion;
- survival rates by sex, pclass, and sex+pclass;
- boolean-mask examples using `&`;
- the exact six-column correlation matrix required by the rubric;
- a heatmap and automatic identification of the two strongest absolute off-diagonal correlations;
- more than four multivariate charts;
- written 2–4 sentence interpretations for the charts;
- an EDA-only z-score standardization check for age and fare.

The correlation matrix uses exactly:

```text
survived, pclass, age, sibsp, parch, fare
```

`adult_male` and `alone` are deliberately excluded from that matrix because they are derived/redundant flags.

### Multivariate chart interpretations

**Survival by sex.** The survival-rate chart compares outcomes across male and female passengers. The observed difference makes sex an important predictive feature and provides a clear first part of the survival story.

**Survival by passenger class.** Survival varies across passenger classes, showing that class contains useful signal about survival. This motivates keeping `pclass` in the predictive pipeline.

**Survival by sex and passenger class.** The combined view shows that survival depends on more than one passenger characteristic. The interaction between sex and class helps explain why a multivariate model is more informative than a single-variable explanation.

**Age versus fare by survival.** This chart combines two continuous variables with survival status. It shows that survival is distributed across a feature space rather than being explained by one continuous variable alone.

**Fare by class and survival.** Fare and class are visibly related, while the survival split within classes adds another dimension to the story. This supports using multiple predictors together rather than treating fare as an isolated explanation.

The actual run-specific values and the automatically identified strongest correlations are written to `outputs/eda_results.txt` and `outputs/eda_findings.md`.

## Modeling requirements covered

`02_modeling.py`:
1. Reads `titanic.csv`.
2. Performs a stratified train/test split before preprocessing.
3. Uses `ColumnTransformer` and `Pipeline` so imputation, encoding, and scaling are fitted only on training data.
4. Trains Logistic Regression, Decision Tree, and Random Forest on the identical split.
5. Reports confusion matrices, accuracy, precision, recall, F1, ROC, and AUC.
6. Saves a labeled Decision Tree visualization.
7. Compares baseline, `class_weight="balanced"`, and SMOTE.
8. Applies SMOTE only inside an imbalanced-learn training pipeline, after the split.
9. Runs `GridSearchCV` over Random Forest `n_estimators`, `max_depth`, and `max_features`.
10. Uses `RandomForestClassifier(oob_score=True, ...)` and reports the OOB score.
11. Predicts fare using multivariate linear regression.
12. Reports MAE, RMSE, R², and Adjusted R².
13. Produces a residual plot and states a heteroscedasticity conclusion.
14. Writes classification and regression metrics as separate metric groups.
15. Selects the classifier with the strongest F1/AUC combination and saves the **complete fitted pipeline**, not just the estimator.
16. Reloads the saved pipeline and confirms it predicts directly from raw/unprocessed feature rows.
